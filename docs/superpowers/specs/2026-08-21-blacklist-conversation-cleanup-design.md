# 拉黑后会话收口设计

## 背景

客服把访客或访客 IP 加入黑名单后，后续消息虽然会被接口拒绝，但已存在的 `open` 会话仍保留 `waiting_since`。客服页面同时对已接访客和历史访客累加等待时间，因此不可见的旧会话仍可能触发“会话等待已超时”循环声音。

## 目标

- 访客黑名单只收口当前商户下指定访客。
- IP 黑名单收口当前商户下使用该 IP 的全部访客，不影响其他商户。
- 收口时将已有会话改为 `resolved`、清空 `waiting_since` 并写入审计事件。
- 在线访客立即收到关闭事件并断开，客服端立即移除在线状态。
- 客服端收到会话收口事件后立即停止该访客的 SLA 计时和重复声音。
- 黑名单接口失败时不执行会话收口；解除黑名单后访客重新打开页面可重新接入。

## 设计

在控制器层增加统一的黑名单会话收口函数。函数接收当前商户、执行客服、命中的访客列表和原因；仅处理属于当前商户的访客。它调用模型层的条件解决函数，避免为从未存在的会话新建记录；若状态发生变化则写入 `resolved` 审计事件。

WebSocket 层增加按访客 ID 原子移除当前连接的函数。连接从在线映射移除后，尽力发送 `force_close` 并关闭 socket；连接在操作期间被替换时重试最新连接。控制器对确实在线的访客发送原有 `userOffline`，保证在线计数正确。

无论访客当前是否在线，控制器都向其分配客服发送 `conversationResolved` 事件。前端收到后，将 `users` 和 `visitors` 中该访客的 `service_status` 改成 `resolved`，清空 `waiting_since`、`waiting_seconds` 和 SLA 已提醒标记，从而马上停止隐藏超时提醒。

## 验证

- 单元测试覆盖访客黑名单和 IP 黑名单调用的租户范围。
- 模型测试覆盖只解决既有活跃会话、不新建不存在会话。
- WebSocket 测试覆盖移除当前连接及连接替换竞态。
- JavaScript 模板一致性测试覆盖客服页面均加载同一逻辑。
- 本地浏览器模拟：先产生待回复会话，再拉黑 `127.0.0.1`，确认访客发送被拒绝、客服列表不再显示超时等待、无重复声音。
